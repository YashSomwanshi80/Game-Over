# Menu, door and bed interaction update — source 0.3.9/code39

Menu clicks now play the existing interface-click asset through one persistent, non-spatial source. Main-menu navigation, character selection, Back/Join/Start, shared settings, guide confirmation, pause and result-menu buttons use it. Disabled buttons stay silent. The source survives scene transitions so a click is not cut off; master volume still applies. No AI hearing event is generated for interface feedback.

Hinged doors choose a swing away from the initiating player's side of the door plane. AI opening uses the agent's approach side. Direction changes only while fully closed, preventing an interrupted door from snapping across its hinge. Existing collision checks still stop blocked leaf motion; there is no fallback that swings into the approaching player. Balcony sliders keep sliding. The timed multiplayer entrance breach chooses its inward swing from Don's outside position. LAN snapshots now carry all 21 swing-direction bits separately from opening fractions, with protocol version 4 requiring matching builds.

Bedroom under-bed access now covers both long sides and the foot using the nearest bed-edge prompt. It tolerates a wider horizontal aim angle and supports standing/crouched views, while requiring nearby, same-storey access and a clear ray to the bed. Bed frame/mattress colliders can be recognized as the intended target; walls and unrelated furniture still block the query. Standing on top of the bed, looking away/up and distant access are rejected. Existing grounded/seen-entry rules, hidden viewpoint and blocked-exit checks remain. Both solo and LAN use the same helper; Don's bed search uses it too. The linen trolley and other hides retain their separate fixed prompts.
